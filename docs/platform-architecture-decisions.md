# Platform architecture decisions — 15 October 2026

Baselines: GPI `b778f19`, FilingLens `271e445`, and source-aligned deployed Risk Studio functions. The platform is a partially verified unified product: the GPI shell and server contracts exist, but a complete authenticated production journey is unverified. Separate Railway projects are not evidence of defective architecture. Service health does not establish integration or correctness.

## Dependency map and risk analysis

The dependency graph is discovery → canonical listing/issuer → source evidence → financial/valuation review → portfolio analytics → investor decision. Research and financial analysis can consume the same scoped sources independently. Human approval precedes durable reviewed valuation publication. Risk Studio consumes approved versions; no component places orders. Inputs, source labels and model output are untrusted at each server boundary.

The principal newly reproduced risks are wrong-issuer valuation attachment after mapping drift, missing/duplicate price provenance, secondary retrieval escaping its requested year or matching irrelevant substrings, and displacement of server evidence warnings by model notes. Six targeted tests failed before the fixes. The complete ordinal register is `platform-risk-register-2026-10-15.json`; unknown evidence is not treated as safe. No active critical exposure or corruption was demonstrated, so no artificial P0 incident is declared.

## Implementation blueprint and verification

The selected patch keeps all arithmetic and approval ownership intact. At consumption, resolve each portfolio position to one current canonical issuer, attach only matching approved versions within the review-age limit, and preserve excluded-version explanations as GPI integration warnings outside the Risk Studio calculation. Require a unique price-source row for every holding, allow the fixed SPY benchmark, validate calendar dates and reject source dates preceding the calculation date. Secondary evidence tools use the same bounded lexical tokens as corpus retrieval and recheck year scope before both search and coverage reporting. Server financial diagnostics take capacity before lower-priority model notes and remain within the shared hundred-record limit.

Acceptance: all six reproduced failures must pass after fixes; existing deterministic calculation/FX/approval/corpus tests remain passing; the wrong-issuer saved valuation never appears in the outgoing provider request; the GPI UI shows the exclusion/reimport warning at desktop/mobile widths; both current real cross-app implementations pass isolated integration tests; production builds, typed checks and required CI pass. Model prompts and financial formulas are unchanged, so no additional paid inference experiment is required for this guard-only patch.

Deploy only tested trees. Stop on identity, source, arithmetic, auth, contract or build regression. Verify terminal deployment states and runtime health separately, then attempt only available authorized workflows. Never replace an unavailable private session with synthetic production auth. Rollback uses prior app/worker deployments and the previously fetched Risk web function source; keep the SEC incident pause intact. No database or data migration is introduced.

Remaining acceptance work: authorized signed-in production smoke; actual SEC access clearance/import/readback; independently labelled wider narrative and multilingual RAG evaluation; complete backup/restore scope; global model budget before expanding users/replicas; real user completion/accessibility measurements; full cross-service trace continuity.
